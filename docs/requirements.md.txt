# Student Management System

**Project Type:** College Mini-Project
**Application:** Web-Based Student Management System

---

## 1. Project Overview

The Student Management System is a web-based application designed to manage student academic information in a college environment.

The system provides two types of users:

* Student
* Teacher

Students can view their academic information, while teachers can manage student-related academic information such as courses, marks, and attendance.

The application will use a web-based frontend, a Java Spring Boot backend, and a MySQL database.

---

## 2. Objectives

The main objectives of the system are:

* To maintain student information in a centralized database.
* To provide students with access to their academic information.
* To allow teachers to manage student academic records.
* To manage courses and student enrollments.
* To manage marks and attendance.
* To provide Create, Read, Update, and Delete (CRUD) operations.
* To demonstrate frontend and backend integration.
* To demonstrate SQL database design and connectivity.
* To provide a simple and user-friendly interface.

---

## 3. User Roles

The system will have two user roles.

### 3.1 Student

Students will log in using:

* Register Number
* Password

Students will primarily have access to their own information.

### 3.2 Teacher

Teachers will log in using:

* Teacher ID
* Password

Teachers will have access to student-related academic management features.

---

# 4. Student Portal

After successful login, the student will be taken to the Student Dashboard.

### 4.1 Student Login

The login page will contain:

* Register Number
* Password
* Login button

There will be no public student registration option because student accounts are assumed to be created by the college.

### 4.2 Student Dashboard

The dashboard will display basic information such as:

* Student name
* Register number
* Department
* Year/Semester
* Course summary
* Attendance summary
* Academic performance summary

### 4.3 Student Profile

Students can view:

* Register number
* Name
* Email
* Phone
* Department
* Year
* Semester

Important academic information will be view-only.

### 4.4 My Courses

Students can view the courses in which they are enrolled.

Information may include:

* Course code
* Course name
* Credits
* Semester

### 4.5 Enrollment

Students can view their course enrollment information.

### 4.6 Marks / Results

Students can view their academic marks and results.

Information may include:

* Course
* Internal marks
* External marks
* Total marks
* Grade

### 4.7 Attendance

Students can view attendance information for their courses.

### 4.8 Logout

Students can log out of the application.

# 7. CRUD Requirements

The system will demonstrate the four basic database operations:

### Create

Add new:

* Students
* Departments
* Courses
* Enrollments
* Marks
* Attendance records

### Read

View:

* Student information
* Department information
* Course information
* Enrollment information
* Marks
* Attendance

### Update

Modify existing records.

### Delete

Remove existing records where appropriate.

The CRUD functionality will primarily be demonstrated through the teacher-side management features.

---

# 8. Database Requirements

The application will use **MySQL** as its database.

The database will contain information related to:

* Students
* Teachers
* Departments
* Courses
* Enrollments
* Marks
* Attendance

Appropriate:

* Primary keys
* Foreign keys
* Constraints
* Relationships

will be used.

The database will be designed and normalized up to:

* First Normal Form (1NF)
* Second Normal Form (2NF)
* Third Normal Form (3NF)

The final database structure will be documented as part of the project.

# 13. Database Connectivity

The Spring Boot backend will communicate with the MySQL database.

The overall data flow will be:

```text
User
  ↓
Frontend
  ↓
REST API
  ↓
Spring Boot
  ↓
Database Access
  ↓
MySQL
```

The database will store and retrieve the application data required by the frontend.
